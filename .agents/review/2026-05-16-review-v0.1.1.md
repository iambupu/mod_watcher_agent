## Findings
### Critical (must fix)
- **backend/app/api/routes_rules.py:110, backend/app/api/routes_rules.py:286** `GET /api/rules/export` is unreachable because the dynamic `GET /{rule_id}` route is registered first. Verified with `TestClient`: `GET /api/rules/export` returns `422` with `rule_id` int parsing error. Suggested fix: move static routes such as `/export` before `/{rule_id}` or constrain dynamic route ordering with tests.
- **backend/app/schemas/watch_rule.py:119** Backend release tests fail: `WatchRuleRead` now requires `intervalMinutes`, while `tests/test_watch_rule_schemas.py::TestWatchRuleRead::test_read_fields` still constructs the documented read model without it. `python -m pytest -q` result: `1 failed, 172 passed`. Suggested fix: either make `WatchRuleRead.intervalMinutes` default to `360` for compatibility or update the contract/tests if the field is intentionally required.

### Warning (should fix)
- **backend/pyproject.toml:3, backend/app/main.py:48, frontend/package.json:4** Version metadata is inconsistent for a v0.1.1 release: FastAPI and frontend are `0.1.1`, but the backend package remains `0.1.0`. Suggested fix: update `backend/pyproject.toml` to `0.1.1` or document why backend packaging is intentionally not part of this release.
- **backend/app/api/routes_rules.py:68** Rule import accepts arbitrary http/https URLs with redirects and no private/loopback host blocking. Because the server performs the fetch, this can be used as a local SSRF primitive if the endpoint is reachable. Suggested fix: reject loopback/private/link-local hosts after DNS resolution, or limit URL import to known trusted hosts.
